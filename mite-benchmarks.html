1. INTRODUCTION & SCOPE

Testing methodology & benchmark purpose.

Engine playing strength depends on opponents, deliberation time controls, transposition table sizing, and match conditions. This report provides full transparency into Mite’s internal test tournament framework.

Methodology & Rating Clarification: All benchmark data documented on this page is derived from 13 automated match series (2,600 games) using alternate-color pairings (100 games as White, 100 as Black per 200-game match series). The approximately 2000 Elo figure is an unofficial internal experimental estimate based on controlled testing against reference opponents (Stockfish calibrated to 2000 UCI limit, TSCP, and Fairy-Max). It does not constitute a certified CCRL, CEGT, IPON, or FIDE rating list. Independent community verification and rating submissions are welcomed.

Standardized Opponents

Opponents were chosen to span canonical historical reference engines to modern calibrated grandmaster-level engines:

  • Stockfish (UCI_Elo = 2000): Calibrated handicap limit representing club/expert play.
  • TSCP v1.81: Historic C benchmark (~1700-1800 Elo) testing tactical baseline execution.
  • Fairy-Max 5.0b: Compact micro-engine (~1850-1900 Elo) testing move ordering against a similar footprint.

Deliberation Time Controls

Tests cover both conventional per-move time limits and fixed search limits to observe search scaling:

  • Conventional (Per-Move): 1s, 3s, 5s, 7s, 10s, and 60s deliberation limits.
  • Fixed Search Time (ST): Exact 0.5s and 2.0s search quotas without dynamic time management.
  • Search Verification: Testing search depth growth from ~8-10 plies (1s) to ~14-16 plies (60s).

Report Purpose

Systematic quantitative validation of Mite's compact C codebase:

  • Search Pipeline Safety: Verifying Null-Move Pruning (NMP) and Late Move Reductions (LMR) without tactical horizon collapses.
  • Evaluation Tuning: Material balance, pawn structures, and piece-square table weights.
  • Stability Audit: Proving zero illegal moves, memory leaks, or crashes over thousands of games.

6. METHODOLOGY & LIMITATIONS

Testing conditions & statistical rigor.

Responsible benchmarking requires documenting testing hardware, tournament protocols, mathematical definitions, and technical limitations.

Tournament Execution Protocol

All matches were executed using Cutechess-cli with strict protocol enforcement:

  • Alternate Colors: Engines alternated White and Black every game to neutralize first-move advantage.
  • Equal Deliberation: Opponents shared identical time allocations under single-thread CPU scheduling.
  • Transposition Tables: 16 MB default hash table (2²⁰ entries) with 64-bit Zobrist indexing.
  • Zero External Books: Engines calculated exclusively from the standard initial chess array.

Standard Formulas

Scores and rating differences are computed using standard computer chess mathematics:

  • Score %: (Wins + 0.5 × Draws) / Games × 100
  • Elo Difference: Calculated using the logistic Elo equation ΔElo = -400 × log10(1/Score - 1) with 95% confidence intervals.
  • Likelihood of Superiority (LOS): Probability that Mite is genuinely stronger than opponent based on game distribution.

Compilation Environment

Standard ANSI C99 compilation pipeline:

  • Compiler: GCC / MinGW-w64 with -O3 -march=native optimization flags.
  • Binary Footprint: ~115 KB static standalone Windows executable.
  • Source Constraints: Under 20 KB source across ~409 lines in src/Mite.c.
  • Dependencies: Zero third-party runtime libraries or external DLLs.

Explicit Testing Limitations & Scientific Integrity

1. Internal Estimate, Not Certified List Rating: Mite’s estimated ~2000 Elo playing strength is an internal benchmark calibrated from controlled matches against Stockfish (UCI_Elo = 2000). It is not an official rating issued by CCRL (Computer Chess Rating Lists), CEGT (Chess Engine Games Tournament), or FIDE.

2. No Opening Book: Because games began without an opening book, matches began from the standard chess starting position (1.e4 or 1.d4). While this evaluates pure internal search and piece-square evaluation, engines in rating lists typically test against diverse opening books (e.g. 8-ply balanced opening books) to prevent repeated pawn transposition lines.

3. Artificial Handicap Opponents: Stockfish’s UCI_LimitStrength mechanism handicaps play by introducing controlled search limits and evaluation noise. While widely used as a reproducible rating anchor, it does not perfectly mimic human or organic rating pool engine behavior.

4. Independent Testing Welcome: We invite chess programmers and rating list operators to benchmark Mite in independent rating pools. Mite is UCI compliant and ready to load into Arena, Cutechess, BanksiaGUI, or automated testing rigs.
